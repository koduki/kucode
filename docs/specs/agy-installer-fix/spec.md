# Feature Spec: Fix `kucode-install-agy` Installer Failure & Patch Release `v0.10.1`

- **Slug**: `agy-installer-fix`
- **Branch**: `fix/agy-installer-skip-path`
- **Delivery Target**: `release-tag` (`v0.10.1`, `versionCode = 12`)
- **Allowed Protected Paths**: None (`[]`)

---

## 1. Problem Statement & Root Cause

In KuCode `0.10.0`, the built-in helper script `/usr/local/bin/kucode-install-agy` (generated by `PosixRuntimeConfig.buildHostCliHelperScripts()["kucode-install-agy"]` in `android/app/src/main/java/dev/koduki/kucode/PosixRuntimeConfig.kt`) fails immediately when users attempt to install Google Antigravity CLI (`agy`) via the ACP panel, KuCode menu (`kucode.setupAntigravityCli`), or integrated terminal.

### Verified Root Cause
- `PosixRuntimeConfig.kt` invokes:
  ```bash
  curl -fsSL https://antigravity.google/cli/install.sh | bash -s -- --skip-path
  ```
- The official Linux/macOS `https://antigravity.google/cli/install.sh` argument parser accepts **only** `-d|--dir <path>` and `-h|--help`. Any other option causes immediate termination with exit code `1`:
  ```text
  [ERROR] Unknown parameter: --skip-path
  ```
  (`--skip-path` is a Windows installer / `agy install` flag, not supported by `install.sh`.)

### Secondary Reliability Defects in `kucode-install-agy`
1. **Early exit on pre-existing or broken `$HOME/.local/bin/agy`**: Upstream `install.sh` exits `0` immediately when `$BINARY_PATH` already exists (`if [ -f "$BINARY_PATH" ]`). If `$HOME/.local/bin/agy` is empty, corrupted, non-executable, or an older `ld-linux-aarch64.so.1` wrapper script, running `kucode-install-agy` skips downloading a fresh binary and either fails later or silently skips upgrading `agy.real`.
2. **Shell RC mutation risk**: Upstream `install.sh` invokes `"$BINARY_PATH" install [--dir "$CUSTOM_DIR"] || true` at the end. Running `install.sh` directly against the user's real `$HOME` (especially with a custom staging `--dir`) risks mutating `~/.bashrc` / `~/.profile` / `~/.zshrc` or disturbing KuCode's PATH precedence invariant (`AGENTS.md`).
3. **Non-atomic replacement on failure**: Downloading directly to `$HOME/.local/bin/agy` or mutating `$HOME/.local/bin/agy` before probing can leave a broken installation if download, checksum, or `--version` probing (e.g. `SIGSYS (159)`) fails.
4. **Post-wrap re-probe under `set -e` and symlink edge case**: After applying the `ld-linux-aarch64.so.1` wrapper, the re-probe ran under `set -e` without structured error reporting, and moving a symlink to `agy.real` would not yield a standalone binary.
5. **Prerequisite check completeness**: Upstream `install.sh` requires `curl`, `tar`, `gzip` (via `tar -xzf`), and `sha512sum` (in addition to `git` and CA certificates).

## 2. Goals & Non-Goals

### Goals
1. Replace the broken `--skip-path` invocation in `kucode-install-agy` with an isolated staging install using the official supported `-d <stage_bin>` option and an isolated temporary `HOME`, cleaned up via `trap ... EXIT`.
2. Preserve the user's real `$HOME/.bashrc`, `$HOME/.profile`, and `$HOME/.zshrc` untouched (zero PATH/RC pollution from `install.sh`'s post-install `agy install` step).
3. Support clean fresh install, broken-file recovery, and idempotent reinstall/upgrade (including upgrading a previously wrapped `agy` + `agy.real` installation without double-wrapping, and removing stale `agy.real` when direct execution works).
4. Guarantee atomic preservation: if download, checksum, binary extraction, or `--version` probing (including `SIGSYS` exit code `159`) fails, any pre-existing working `$HOME/.local/bin/agy` (and `agy.real`) remains intact.
5. Preserve `ld-linux-aarch64.so.1` exec wrapper fallback, `SIGSYS (159)` diagnostic output and exit code `159`, `agy acp --help` verification, and user-first `PATH` ordering.
6. Ensure `curl`, `git`, `tar`, `gzip`, and `sha512sum` are verified prior to invoking `install.sh` (installing missing Debian packages via `apt-get` when absent).
7. Bump KuCode version consistently to `0.10.1` (`versionCode = 12`) and publish GitHub Release `v0.10.1` after merge to `main`.

### Non-Goals
- Changing `kucode-install-copilot`, `agy acp` JSON-RPC client logic, `RuntimeInstaller.ensureExtracted` persistence semantics, or `runtime-assets.lock.json`.
- Adding unofficial third-party binary patches or untrusted installer URL override environment variables (`https://antigravity.google/cli/install.sh` MUST remain hardcoded).
- Claiming physical XREAL AURA real-device verification from Linux CI/JVM/Node tests (remains `NOT RUN`).

## 3. Public Contracts & Behavioral Requirements

### 3.1 `kucode-install-agy` Helper Script Contract
- **Location**: Generated by `PosixRuntimeConfig.buildHostCliHelperScripts()["kucode-install-agy"]` in `android/app/src/main/java/dev/koduki/kucode/PosixRuntimeConfig.kt` and synced with mode `0755` into `/usr/local/bin/kucode-install-agy` by `RuntimeInstaller.prepareRuntimeDirectories`.
- **Shebang & Strict Mode**: Starts with `#!/usr/bin/env bash`, enables `set -euo pipefail`, and passes `bash -n`.
- **PATH Preservation**: Ensures `$HOME/.local/bin` precedes standard system directories while preserving existing `$PATH` entries (no clobbering of user/SDK toolchains before `/usr/local/bin:/usr/bin`).
- **Prerequisite Check**: Before invoking the upstream installer, checks for `curl`, `git`, `tar`, `gzip`, and `sha512sum`; if any is missing, runs `apt-get update` and `DEBIAN_FRONTEND=noninteractive apt-get install -y --no-install-recommends ca-certificates curl git tar gzip coreutils`.
- **Official Installer Invocation**:
  - Creates a temporary staging directory via `mktemp -d` with `trap` cleanup on `EXIT`.
  - Runs `curl -fsSL https://antigravity.google/cli/install.sh` piped to `HOME="$STAGE_HOME" bash -s -- -d "$STAGE_BIN"` (where `$STAGE_HOME` and `$STAGE_BIN` are subdirectories inside the temporary staging directory).
  - MUST NOT pass `--skip-path` or `--skip-aliases` to `install.sh`.
  - MUST keep `https://antigravity.google/cli/install.sh` hardcoded (no untrusted URL override env var).
- **Binary Verification & Atomic Installation**:
  - Verifies `$STAGE_BIN/agy` exists and is executable; if missing, logs `[kucode] ERROR:` to stderr and exits non-zero without modifying `$HOME/.local/bin/agy`.
  - Probes `"$STAGE_BIN/agy" --version` under `set +e`:
    - **Direct execution succeeds (`PROBE_RC == 0`)**:
      - Copies/moves `$STAGE_BIN/agy` atomically (`chmod 755` + `mv -f` via temporary file in `$HOME/.local/bin`) to `$HOME/.local/bin/agy`.
      - Removes any stale `$HOME/.local/bin/agy.real`.
    - **Direct execution fails (`PROBE_RC != 0`) and `/lib/ld-linux-aarch64.so.1` exists and `/lib/ld-linux-aarch64.so.1 "$STAGE_BIN/agy" --version` succeeds**:
      - Installs the staged binary atomically to `$HOME/.local/bin/agy.real` (`0755`).
      - Writes an executable (`0755`) `/bin/sh` wrapper atomically to `$HOME/.local/bin/agy`:
        ```sh
        #!/bin/sh
        exec /lib/ld-linux-aarch64.so.1 "$HOME/.local/bin/agy.real" "$@"
        ```
      - Re-probes `"$HOME/.local/bin/agy" --version` under `set +e`; if the wrapper probe fails, prints `[kucode] ERROR: agy --version failed (rc=...)` and exits non-zero.
    - **`PROBE_RC == 159` (`SIGSYS`)**:
      - Prints `[kucode] ERROR: agy exited with SIGSYS (159) — Android seccomp blocked a syscall (e.g. faccessat2).`, probe output, and `PROOT_NO_SECCOMP` guidance to stderr, and exits `159` without modifying any pre-existing `$HOME/.local/bin/agy`.
    - **Any other probe failure**:
      - Prints `[kucode] ERROR: agy --version failed (rc=<rc>): <output>` to stderr and exits `<rc>` without modifying any pre-existing `$HOME/.local/bin/agy`.
- **Post-Install Verification & Output**:
  - Prints `[kucode] Installed: <version-output>`.
  - Runs `"$HOME/.local/bin/agy" acp --help >/dev/null 2>&1`:
    - On success: prints `[kucode] Verified: 'agy acp' ACP v1 server subcommand is ready.`
    - On failure: prints `[kucode] WARNING: 'agy acp --help' did not succeed; ensure agy is up to date.` to stderr (non-fatal).
  - Prints `[kucode] Next step: run 'agy acp --login' (recommended on Android XR) or 'agy' to sign in.`
